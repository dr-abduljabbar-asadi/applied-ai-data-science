COLD OPEN
"You already know loops and functions. This is the 20-minute tour of what's

LEARNING OBJECTIVES

- Avoid the mutability/aliasing bugs that corrupt datasets silently.

PREREQUISITES: EP1.

OUTLINE + WHAT TO DEMO

   (empty list/str/0/None are falsy), ternary `x if cond else y`.

EP4 — OOP FOR ML: CLASSES, DUNDER METHODS & THE fit/predict PATTERN
~20 min · SHORT · ESSENTIAL
================================================================================

COLD OPEN
"Every model you'll ever use — LinearRegression, StandardScaler, a PyTorch module —

LEARNING OBJECTIVES
- Write classes with __init__, methods, and the key dunder methods.
- Understand the ML convention: hyperparameters in __init__, learned attributes end
  with an underscore (e.g., self.mean_).

PREREQUISITES: EP2.

OUTLINE + WHAT TO DEMO
1. Class basics fast (4 min): class, __init__, self, instance vs class attributes,
   methods.
2. Dunder methods that matter for ML (6 min):
   - __repr__ (readable model objects), __call__ (make an instance callable, like a
     layer), __len__ / __getitem__ (the Dataset protocol used by PyTorch DataLoaders).
3. The fit/transform convention (7 min) — build a StandardScaler by hand:
       class StandardScaler:
           def fit(self, X):
               self.mean_ = X.mean(axis=0)
               self.std_  = X.std(axis=0)
               return self
           def transform(self, X):
               return (X - self.mean_) / self.std_
           def fit_transform(self, X):
               return self.fit(X).transform(X)
   - Explain the trailing-underscore convention and why fit returns self (chaining).
4. Inheritance in one breath (3 min): base class + subclass, super().__init__();
   tease that scikit-learn gives you methods for free via mixins (next episode).

ARTIFACT
A working StandardScaler-style transformer class with fit / transform / fit_transform.

PITFALLS
- Fitting on the whole dataset then splitting = data leakage (foreshadow ML track).
- Mutating X in place inside transform.

"You built the pattern. Next — the flagship — we make our own class a REAL
scikit-learn estimator that drops into Pipeline and GridSearchCV."

EP7 — NUMPY BROADCASTING FROM SCRATCH   [HOOK — film first]
~15 min · SHORT · ESSENTIAL
================================================================================

COLD OPEN
"How do you subtract a vector of column means from a whole matrix — with no loop?
Broadcasting. It's two rules, and it's everywhere in ML."

LEARNING OBJECTIVES
- State and apply the two broadcasting rules.
- Replace loops with broadcast operations and know when shapes are incompatible.

PREREQUISITES: EP6.

OUTLINE + WHAT TO DEMO
1. The problem first (2 min): normalize a (100, 5) matrix by per-column mean —
   show the ugly loop, then the one-liner.
2. The two rules (4 min): align shapes right-to-left; dimensions are compatible if
   equal or one of them is 1; missing leading dims treated as 1.
       (100, 5) - (5,)      -> ok, subtract row vector from each row
       (100, 5) - (100, 1)  -> ok, subtract column vector from each column
       (100, 5) - (100,)    -> ERROR, explain why, fix with [:, None]
3. Live shape gymnastics (5 min): np.newaxis / None, reshape to make broadcasts work;
   outer operations a[:, None] * b[None, :].
4. Real ML use (4 min): z-score normalization (X - mean) / std; pairwise squared
   distances between rows using broadcasting (the classic KNN trick):
       diff = X[:, None, :] - X[None, :, :]
       dists = (diff ** 2).sum(-1)

ARTIFACT
z-score normalization + a pairwise-distance matrix, loop version vs broadcast version,
with timing showing the speedup.

PITFALLS
- The (100,) vs (100,1) trap.
- Broadcasting blowing up memory (the (N, N, D) intermediate) — mention it.

SEO / HOOK NOTES
Title: "NumPy Broadcasting Explained From Scratch" / "NumPy Broadcasting: The 2 Rules
That Kill Your Loops". Evergreen, high-confusion search, usually buried inside long
courses — own the standalone.
